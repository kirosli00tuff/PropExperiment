## Implementation choices (none can change a trade)

1. Each member dataclass takes its tables as defaulted fields (ngpre `ngs`; apipre `wpsr`,
   `full_sessions`, `monday_holidays`, `api_dropped`; eiafade `wpsr`; eiamom `wpsr`,
   `nyse_not_full`), defaulting to the frozen literal tables; the factories pass only the root.
   Tests inject one-row tables for cases the frozen tables never contain (a holiday-Monday standard
   week, a 12:58/12:59/16:00 row, a NYSE-listed regular Wednesday).
2. apipre keeps only the Tuesday's two captures (close ticks, instrument_id) across the trade-date
   change, and uses them only on the trade date W with W - 1 day = that Tuesday. Bars are matched
   by exact UTC open instant; a Tuesday is captured only when the next calendar day is an event W.
3. _event_common.py is a copy of E.3's K2 helpers (clock_minute, ct_open_ns, price_ticks,
   exit_items, check_exposure); nothing is imported from k2 or from Coder A's helpers. apipre
   imports only ENERGY_FULL_SESSIONS from _calendar.py.
4. eiafade's 13:28 and 13:13 are literal constants as the spec writes them; a test pins
   13:28 = C - 2 from the frozen O/C table.
5. DROPPED_* reasons are "<check verdict>: <section 11's words, condensed>"; the pin checks the dates
   against the JSON verdicts and against section 11's hard-coded list, and the verdict prefix.
6. The NGS drop rule in the generator is verdict "updated" or "drop_*"; the generator asserts the
   result equals section 11's list. API_DROPPED_WEEKS is computed from the check's api_weeks.
7. My test kit is my own copy (Day, frame, run, ForcedLimitRules, fills, intents); it does not import
   Coder A's test module. MCL and NG are not hard-limit products, so D9.7 is shown with a test-only
   rules subclass that queues a `price_limit_exit` (as Coder A did).
