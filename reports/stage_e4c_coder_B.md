## Implementation choices (none changes a trade)

- One shared core (`FixEvent`) for ldnrev, ldnmom, tkypre and tkypost. Each member gives one Plan per event date
  (the signal reads, the entry bar, the exit bar) and a side function. ecbfix has its own two-leg state machine,
  which tells the legs apart by the position's sign (leg 1 short, leg 2 long).
- The members build their plans at construction from the literal tables. Each member takes optional table arguments
  (the defaults are the frozen tables) so that tests can move or drop a row. A missing clock row for an event date
  raises at construction; it cannot happen with the frozen tables (pinned).
- K3-L-02: no fix instant is computed at run time. The only zone used at run time is ZoneInfo("America/Chicago"), in
  _event_common.ct_open_ns, which turns the tables' CT wall times into UTC. It works as the template's CT clock does
  and as coder A's _port_common does. A test asserts that no other zone appears in any of my k3 files.
- TGT_CLOSING_DAYS keeps all 48 of the check's dates (2019-2026, including dates outside 2019-04..2026-06).
  GOTOBI_OR_TOKYO_MONTH_END stops at 2026-06-19 and so drops 2026-06-30. No member can trade outside FX_FULL_SESSIONS
  (2019-05-01..2026-06-19) in either case.
- The `_calendar.SOURCE_SHA256` pin also covers rules/sessions.py, because FX_FULL_SESSIONS depends on it (K3-L-11).
- I wrote the generator reports/stage_e4_briefs/gen_k3_tables.py. The brief names it but does not list it among my
  files.
