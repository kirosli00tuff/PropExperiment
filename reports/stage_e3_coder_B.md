## 3. How the engine calls a single-leg member

screening/stage_e_engine.py iter_minutes (lines 239-262) builds the grid from the minutes at which any of
the member's legs has a bar, and StageERules.call_member (stage_e_rules.py lines 443-445) passes
`view.bars[r]` for the legs present. So a one-leg member is called only on minutes where its leg has a
bar; a missing bar means no call at that minute. The members still return () on a None bar
(`test_a_none_bar_is_no_decision`), and every named bar is matched by its exact UTC open instant, so a
missing named bar is simply never seen.

## 5. Implementation choices (none can change a trade)

1. **Reading a bar's open.** The freeze's static check refuses the attribute `.open` (BANNED_NAMES bans
   the builtin `open` as a name *and* as an attribute; `check_member_source` on `x = bar.open` returns
   `banned_name: .open`). predrift needs the 08:30 bar's open, so `_event_common.bar_open_price` reads
   it as `dataclasses.asdict(bar)["open"]` (dataclasses is on the allowlist). The value is identical to
   `bar.open`. **Flag for the lead:** this reads a field the check's wording seems to forbid by
   accident; an auditor may call it a workaround. Any member that reads a bar's open (MemberCoder-A's
   ports, if they do) meets the same refusal. Alternatives: `astuple(bar)[1]` (position-dependent), or
   a harness change (not mine to make).
2. One shared core (`FixedSideEvent`) for the three fixed-side members; predrift has its own
   `on_minute` because of the signal. Each member module holds its literal offsets and windows as named
   constants.
3. Named bars are matched by exact UTC open instant, computed from the trade date as the CT calendar
   date and CT clock minutes (S0.4, L-14). Once the named entry bar has been seen, the day's entry is
   used, whether the member emitted, skipped (halt, guard, s = 0) or the engine refused.
4. "No exit pending" is read as: the pending quantity is non-zero and opposite to the position. This
   includes the engine's queued forced flatten, so the member does not stack an exit on top of it.
   Positions only ever come from the member's own entry, so "any pending" would behave the same.
5. A member constructed for an exposure it does not trade raises ValueError (construction only).
6. `_releases.py` keeps T_a as "HH:MM" CT text and dates as ISO text, as the brief specifies. The
   members parse them once at construction. The generator keeps the drop list as a constant (DROPPED,
   empty) and rewrites `_releases.py` whole.
