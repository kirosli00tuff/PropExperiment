## 1. How to read

- **Pair score.** S = 0.50 L1 + 0.50 L2, on 0 to 4, from unrounded criterion scores (spec 5).
  L1 = 0.30 D1 + 0.15 D2 + 0.15 D3 + 0.15 D4 + 0.10 D5 + 0.15 D6 (contract, spec 3).
  L2 = 0.40 E + 0.15 R + 0.15 A + 0.15 D + 0.10 Rel + 0.05 P (firm x contract, spec 4). E.28's sim-fill criterion F
  is dropped. Pairs are ordered by S. Equal S at 2 decimals (half-up) is a tie, broken by lower m*, then higher L1,
  then lower cost per attempt, then code, then firm. The score run reports 21 tie groups: 19 were broken by m* and 2
  (M6A, M6E) by cost per attempt. Because of this rule, a listing can put a pair with a slightly higher unrounded S
  below one with a lower S when both round to the same 2 decimals (RS-A3P and RS-RELTOP0 in section 6 show this).
- **Gates.** Layer 1 fails if D4 = 0, if sigma_60 < 2 x c_RT (with c_RT = S + 0.5 ticks), or if sigma_60 is unknown.
  Layer 2 excludes a pair if the firm does not list the product on its 50K plan, if A = 0, or if the firm does not
  accept British Columbia residents. In this run no pair has A = 0 (the rater reports no gate) and all five firms
  accept BC residents (F4 firms.bc_accepts true for all five), so every Layer 2 exclusion is "not listed".
  E.28's L1 >= 2.00 and no-zero gates are not used (OC-7). L1 < 2.00 is flagged, and variant L1min2 applies the
  2.00 gate.
- **Spread.** S = 1 tick for every one of the 46 scored codes in the primary run (NQ is not scored). For 13 codes the
  1 is sourced under LR-S (median 1, or every mean below 1.5, or a one-tick statement); for the other 33 it is 1 (u).
  HG is one of the 13 in the frozen F4 but is 1 (u) by the erratum LR-S1e (section 7), which makes 12 and 34. So c_RT = 1.5 ticks and the gate threshold
  2 x (S + 0.5) = 3.00 ticks hold for every code, and declared variant spread1 is a no-op.
- **Unknown rules applied** (counts from the score run): S = 1 (u) for 33 codes (HG adds the 34th by erratum);
  Sat (iii) unknown -> 0 for 18; D5 k price unknown -> 1 for 14; J unknown -> 1 for 8 (all 8 are sigma-unknown
  codes); L ADV unknown -> 1 for 7; D2 a unknown -> 1 for 4 (crypto); Sat (i) "a larger sibling exists, ratio
  unknown -> holds" for 8 codes (the five micro grains, QM, MCL against QM, MBT); D5 h unknown -> 1 for SI.
  On the 103 ranked pairs: P "API rate limit unknown -> deduction" 77, P "VPS near Chicago unknown -> deduction" 57;
  Rel "payout unknown -> no deduction" 77 (four firms: Bulenox, Lucid, MFFU, Tradeify; accepted ScoreCoder reading;
  the lead confirms that unknown payout facts take no Rel deduction). D2 c is marked provisional for 34 codes whose
  family has a member with unknown notional ADV. The lead's reading, as corrected by review RV1 S2: no code with a known notional
  loses c = 1 to a code with an unknown notional in metals, crude, grains or rates, so the provisional values stand
  there; crypto's c is 0 throughout and undetermined (ETH, whose notional is unknown only for lack of an F3 close,
  very probably holds the family's largest notional ADV).
- **Who set what (spec 6).** The blind rater (BlindScorer2-OpusXHigh, fresh, masked sheets only; rater 1 superseded)
  rated D2 a and b, D3 s1 s2 s3, D4 Sat (iii), D6, R, A and the Rel deductions. The lead used the rater's primary

- **Data-access encoding.** The score run's 55 "input checks": 47 (F4 o_owned_36m against F2 o) are all the FT-1 boolean

## 3. Layer 2 and the full pair table

### 3a. Every ranked pair (103)

m* = mu*_mkt / sigma_60 and m10K = mu10K_mkt / sigma_60. In ticks they are the market-case break-even and
10K-probability thresholds of E.28's model with T 20 and sigma_T = sigma_1 (OC-4). E = 0.75 s(m*; 0.20) +
0.25 s(m10K; 0.30). A threshold above the grid cap max(4, ceil(0.30 sigma_60)) ticks scores 0. D is the mean of the
room_a and room_b bands. "Rel (deductions)" names the deductions applied. The fee is the firm's all-in round trip
("RR-05 (u)" marks Lucid's u-rule fee). The tie-break cost per attempt is the market case (E.28's evaluation fees per
attempt at mu = 0 with d = -c_mkt; econ field cost_per_attempt_mkt_mu0), per the lead's EconSetup ruling and spec 4;
the limit-case value (E.28's d = -F_rt / v; econ field cost_per_attempt) is shown beside it and is not used. The two
ties this level decides (Tradeify over Topstep for M6A at ranks 94/95 and for M6E at 101/102) keep their order under
either value (market 95.83 against 98.82 and 98.35; limit 95.83 against 202.80 and 206.89). Econ note (review RV1
S3): for Bulenox x CL and Bulenox x NG, blocks primary and spread1, the bisection did not confirm (confirmed: false),
