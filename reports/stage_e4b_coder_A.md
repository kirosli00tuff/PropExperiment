### F-7 diff note (strategy/members/k4/ovr.py against strategy/members/k5/ovr.py)

`diff -u strategy/members/k4/ovr.py strategy/members/k5/ovr.py` changes these things only:

1. **Clock.** K4's literal `DECISION_TIMES_CT` is replaced by
   `DECISION_STEP_MIN = 60` and `decision_times(o, c)`, which is t = O + 60k for k >= 1 while
   t <= C, from the frozen O and C, stored per instance as `self._times`. The trading window's end
   follows from the clock: K4's literal `WINDOW_END_CT = 14:00` ("the last exit fill is 13:59")
   becomes `WINDOW_END_AFTER_LAST_T_MIN = 60` applied to the last t. Applied to K4's energy O and C
   (08:00, 13:30), the formula returns K4's five literal times 09:00..13:00; a test asserts this.
2. **Calendar table.** `ENERGY_FULL_SESSIONS` from k4._calendar is replaced by `METALS_FULL_SESSIONS`
   from k5._calendar.
3. **Value floor.** K4's `MIN_VALUES = 80` is replaced by `VALUE_FLOOR_PERCENT = 80` and
   `min_values(n_times)`, which is ceil(80% x n_times x 20): 80 on MGC, the same as K4, and 64 on MHG.
   It is stored as `self._min_values`, and the check reads `len(values) < self._min_values`.
4. **Non-rule changes:** module path k4 -> k5, MEMBER_ID, factories make_mcl/make_ng -> make_mgc/make_mhg,
   `__all__`, and docstrings and comments. Every other line is identical: the signal, C10,
   reference dates, warm-up, percentile cuts, tie, entry, exit, early halt and state handling.

## Implementation choices (none can change a trade)

- `_port_common.py` holds shared plumbing only, as in K4. Coder B's `_event_common.py` and
  `_releases.py` are neither read nor imported.
- ovr computes its clock and floor from the frozen O and C instead of carrying literals. This is the
  spec's "t = O + 60k while t <= C" and "80% of the possible values"; tests pin both results as
  literals.
- The tests carry their own synthetic kit, adapted from tests/test_e4_k4_members_a.py and not
  imported from it. Expected times are written as literals per root, not derived from the code.
- D9.7 cannot fire on MGC or MHG with the real rules: both are DCB-only, not in
  rules.price_limits.HARD_LIMIT_PRODUCTS, and a test asserts this. The D9.7 tests therefore use a
  test-only `ForcedLimitRules` subclass that queues the engine's own price_limit_exit, as K4 did.
- Moved and dropped events: my four members read no release or auction instant, so a moved event
  cannot move any of their decision minutes. The table analogue is covered:
  - an early-halt date is not in METALS_FULL_SESSIONS and is not traded or referenced;
  - a date with fewer than 20 table dates before it is not traded.
- Extra check beyond the brief: in-memory mutation checks from a scratch script, with no file
  changed. All 8 mutants were killed:
  - ovr: halt check removed, floor +1 and -1, t = O added to the clock;
  - cp2: buffer 3 ticks, hold 74 bars;
  - cp1: signal bar O+28;
  - cp3: C_d taken at C-2.
